# 效率记录模板

交接 §6 的要求：本轮目标是开发交付效率与可靠性，**不承诺**旅程运行更快或 token 更少。
没有可靠前后对照就写「效率效果待实测」，**不要为了填数字重复无意义任务**，
也不要拿测试通过数或 PR 数替代效率。

---

## 怎么用

1. 改动**之前**复制一份本模板，填「基线」段。
2. 改动**之后**填「实测」段。
3. 把两份放到 `docs/efficiency/` 下，命名 `YYYY-MM-DD-<任务名>.md`。
4. 在 `docs/agent-environment-validation.md` 里引用它。

## 示例：修"轮询丢掉回复草稿"

> 这是一个**格式示例**，数字为占位，请替换为真实测量。

元信息：任务类型 = 修 bug；执行人熟悉该模块（改前的人不熟悉）。

基线：定位 25min（需要读 1100 行 H5 才知道 state 是单一对象）、
实现 40min、验证 15min、返工 20min（发现草稿按旅程存导致信号切换后误投）、
人工补充 3 次（问架构、翻旧验证记录、搬运运行结果）。

实测：定位 4min（`docs/FEATURE-MAP.md` 直接指到回复入口）、
实现 20min、验证 3min（`npm run check`）、返工 0、
人工补充 0 次。

限制：单次样本；执行人比基线更熟悉，且基线执行人不是同一批；
**不代表所有任务都有同等收益**。

运行开销：草稿从"渲染时读写 DOM"改为"按信号 ID 存内存"，
每次重渲染多 1 次查表，可忽略；数据库体积不变。
