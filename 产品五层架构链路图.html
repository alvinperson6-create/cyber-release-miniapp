产品核心 5 层架构 — 电商下单实际链路

从你点击「提交订单」到订单落库，请求穿透 5 层的完整路径

第 1 层
用户终端层
APP / H5 / 小程序
职责：界面渲染、用户交互、本地状态管理
本链路动作：选好规格 → 点击「提交订单」→ 前端校验收货地址/优惠券 → 组装下单参数 → 发起 HTTPS 请求
↓
第 2 层
接入网关层
CDN / WAF / API 网关 / 负载均衡
职责：统一入口、HTTPS 卸载、身份认证、限流熔断、请求路由
本链路动作：WAF 过滤恶意请求 → 网关校验 Token 确认本人 → 限流判断没刷单 → 路由转发给「订单服务集群」
↓
第 3 层
业务应用层
订单服务 / 商品服务 / 库存服务 / 支付服务
职责：核心业务逻辑编排、规则计算、事务控制
本链路动作：订单服务编排全流程 → 调商品服务查价格 → 调库存服务预占库存 → 算优惠/运费 → 生成订单号 → 拉起收银台
↓
第 4 层
数据服务层
MySQL / Redis / 消息队列 / 搜索引擎
职责：数据持久化、缓存加速、异步解耦、分布式协调
本链路动作：Redis 原子扣减库存 → MySQL 写入订单主表+明细 → 发 MQ 通知物流/积分服务 → ES 同步商品可售状态
↓
第 5 层
基础设施层
服务器 / K8s 容器编排 / 监控告警 / 日志链路 / 配置中心
职责：底层算力调度、运维保障、可观测性
本链路动作：K8s 把订单服务调度到健康节点 → Prometheus 记录下单 QPS → ELK 写入请求日志 → 配置中心下发限流规则
第1层
用户看得见的
界面、交互、按钮
第2层
大门保安
鉴权、限流、路由
第3层
业务大脑
编排逻辑、算价格
第4层
仓库管理员
存数据、缓存、异步
第5层
地基水电
算力、监控、运维
联想法：把一次下单想象成「去餐厅吃饭」
第1层（终端） = 你坐下来看菜单点菜 → 第2层（网关） = 门口迎宾确认你有预约 → 第3层（业务层） = 服务员把你的需求告诉后厨、算总价 → 第4层（数据层） = 后厨查冰箱有没有食材、记账本登记 → 第5层（基础设施） = 整个餐厅的水电煤气、消防、监控
