## 关键工程约束（后续改动必须遵守）

1. **边界由检查器强制**，不是文档约定：renderer 不得 import serving/碰 DB；shared 纯模块；SQL 只在 `store.js`；serving 不依赖 legacy/tests。
2. **数据路径锚定**：`DB_PATH` → `CYBER_RELEASE_DB` → `server/data.db`，不随代码搬迁。
3. **回复必须带 signalMessageId/encounterId**，缺目标直接拒绝，不做"推断最新信号"兼容。
4. **提交后复核**：状态、输入快照（补给位）、租约持有者。结果语义 5 种。
5. **defer ≠ retry**：正常等待不消耗错误重试次数。
6. **注入 adapter 也会被 runtime 包一层记账**，避免绕过预算。

### 关键坑：Node 不走系统代理

浏览器能开、服务器连不上。实测：

| 手段 | 结果 |
| --- | --- |
| macOS 系统代理 127.0.0.1:7897 | Node 直连仍本地出口 → 451 |
| Node 内置 `--use-env-proxy` | **无效**（三种组合都走本地出口） |
| `undici` + `ProxyAgent` | **有效** |

解法：`serving/adapters/http-client.js`，JEV 适配器用 `JEV_PROXY` 启用。
本机代理端口是 **7897**（查 `scutil --proxy | grep -A2 HTTPSEnable`）。

第二个坑：沙箱会同时注入 `HTTP_PROXY` 和 `HTTPS_PROXY` 且指向不同代理。
初版按 `HTTPS_PROXY || http_proxy` 取值 → https 请求被污染，表现为
"配了代理但出口 IP 没变"。已改为 https 只读 HTTPS 代理，
由 `tests/proxy-client.test.js` 钉住。

## 修复的 12 个真实缺陷

见 `docs/agent-environment-validation.md` §7。其中几个值得记住：
- store 曾是模块级单例 → 两个 runtime 共享 DB（改为 `createStore()` 工厂）
- 注入的 adapter 绕过统一记账 → 预算形同虚设（加 `withLedger()` 包装）
- 5 处 SQL 用 `@name` 却按位置传参 → 运行时抛错、调度静默重试
- 静态白名单收紧过头 → 公开资源全 404（现在同时断言"公开可达 + 私有不可达"）
- 冒烟脚本把"暂停"报成"未覆盖：无" → 不诚实验证结论

## 教训

**验证工具自己出错比没有验证更危险。** 收紧边界时必须同时断言"该可达的仍可达"，
否则会把功能改坏而检查全绿。
