## 1. 产品目标与不能丢失的体验

用户把一句烦恼交给一只有人设的虚拟生物，选择水域和回信时间；生物随后寄来与这句话有关的荒诞经历。现有产品还包含四集命运轨迹、配图、解锁、档案和世界脉搏。

要强化的体验是：

> 用户随手放下的一句话，让一只锦鲤活出了一段出乎意料、但又能理解为什么会发生的人生。

具体目标：

1. 故事能区别具体处境，不把所有烦恼压成“焦虑 / 愤怒 / 难过”。
2. 情绪或处境影响生物行为，行为推动事件，事件导向结局。
3. 生物有自己的口吻、选择和意外；用户不必每天照看它。
4. 已经展示的事件和结局保持一致，后续互动影响未来。
5. 新增判断成本、失败率、重写次数和等待时间可观测。

不要把产品改成心理诊断、劝导课堂或必须签到喂养的养成任务。黑色幽默继续存在，但主要针对处境、生物自身和荒诞规则，不要靠贬低用户维持笑点。

## 3. JEV 的职责与验证原则

参考资料：

- 用户提供的手册：<https://my.feishu.cn/docx/MBD3dENMlo8V1Qx8IotcOVVUnQh>
- 官方介绍：<https://docs.typesafe.ai/introduction>
- 问题类型和独立问题：<https://docs.typesafe.ai/primitives>
- 输入与语言限制：<https://docs.typesafe.ai/concepts/state>
- 置信度说明：<https://docs.typesafe.ai/confidence>

交接时已读取手册正文及以上官方页面。执行接入前核对实际接口、SDK/模型版本、计价和字段，不能从本文猜测 API。

能力分工：

| 组件 | 应承担的工作 |
| --- | --- |
| JEV | 针对给定材料进行有限选项、明确量表、是非命题判断 |
| 文本生成模型 | 写故事、写回信、提出复杂剧情候选、修复有明确缺口的文本 |
| 程序 | 合法动作过滤、状态更新、阈值、预算、随机性、时间、幂等、存储、副作用 |
| 图片生成模型 | 根据已接受故事的画面契约生成图片 |
| 独立评估 | 核验真实质量，不能仅以在线 JEV 自评分证明改造有效 |

注意：

- 有限输出不等于语义正确；`confidence` 不是用户喜欢概率，也不是事实正确的保证。
- `Choice` 适合有限选项；`Score` 适合有文字定义的有序等级；`Noul` 表示命题为真的概率，交接时文档说明它没有单独的 `confidence` 字段。
- 同一请求中的问题彼此独立，不能让第二题暗中读取第一题答案。代码组合答案；确有依赖时再发下一轮。
- 中文、反话、网络梗、混合情绪需要单独评估，不能引用官方英文案例数字推断本项目表现。
- 当前文档说明 JEV 输入为文本；可以检查画面描述与剧本是否一致，不能声称直接验收最终图片。图像验收需人工或实际支持图像的工具。
- 不照搬手册的速度/成本倍数，也不预先承诺一定省钱。这里新增判断可能增加总成本。
- 规则能准确完成的事情直接用代码：四段、字段、字符长度、时间先后、资源余额、权限和状态迁移。

## 4. 第一阶段：具体烦恼识别与故事因果验收

### 4.1 用具体处境约束创作

对照例子：

| 原始输入 | 可被原文支持的处境 | 可能的创作方向，仅为示例 |
| --- | --- | --- |
| 每天都干不完，我真的想歇一下 | 任务过量、希望休息 | 乌龟造了自动干活机器，最后忙着给机器安排休假 |
| 事情不多，但老板总在下班前找我 | 个人时间边界被打断 | 锦鲤每次游到湖口，都被叫回去开最后一个短会 |
| 做了很多，最后功劳全算别人头上 | 付出未被承认、归功不公 | 云朵下雨一整天，彩虹出现五分钟获得降水奖 |

实现一个小而明确的处境集合，建议起点：任务过量、失去选择权、时间边界被侵占、努力未获承认、对结果不确定、关系失落、难以拒绝请求、积极期待或喜悦。

这不是永久分类体系。允许多个成立；每项可以是“原文支持 / 原文反驳 / 未表达 / 含糊”。不要把未知强行变成否，也不要把讽刺句中的正面词当作快乐。

保留原始输入作为创作依据，不要只给生成模型几个标签。要让每项被采用的判断能回到原始文本；可由程序预先划分句段、让判断选择合法句段 ID，再由程序恢复原文，不要求 JEV 自由生成证据引用。

将可用判断确定性地组装成简短创作契约，包含：

- 原文与被支持的具体处境。
- 生物、水域、时间锚点、既有人设。
- 必须表现的行为倾向和需要避开的表达。
- 四集结构、不可虚构的用户事实边界。
- 契约版本、判断来源与降级状态。

字段命名由执行 Agent 根据当前项目决定，不机械照搬大型框架。JEV 不可用时可回到现有生成路径，但记录真实的降级状态。

### 4.2 验收要拆成可以检查的问题

至少覆盖：

1. 生物是否因原文支持的处境改变了具体行为？
2. 关键行为是否在文本中推动了下一事件？可逐个检查相邻事件，避免一题要求长链证明。
3. 结局是否得到前文铺垫，而非突然宣布？
4. 文本是否把用户没提供的个人信息当作事实？区分虚构 NPC 与对用户本人的事实断言。
5. 主要调侃对象是否落在用户明确表达的边界之外？
6. 回信、地点、结构化画面描述是否存在明确冲突？

反例：“因为你焦虑，所以我成了海底市长。”只有因果连接词，不足以证明故事写出了行为和事件之间的联系。

至少包含这些验收挑战：只提情绪词、把因果反过来、情绪换成另一种也完全通用、前文无铺垫、地点矛盾、擅自编公司/人名、暗中贬低用户、结构正确但内容空白。

不要把“好笑”“有共鸣”作为未经校准的硬门槛。可将其作为独立盲评维度。对合理超现实设定的检查应基于故事内部一致性，不要求所有剧情符合现实物理。

### 4.3 接受、修复与降级

建议流程：

```text
原始输入
  → 处境判断（可降级）
  → 程序组装创作契约
  → 文本模型生成剧本
  → 程序检查结构
  → JEV 检查语义缺口
  → 程序决定：接受 / 修复一次 / 明确降级
  → 冻结本轮已接受故事
  → 派生回信和画面描述
  → 图片生成与持久化
```

- 默认最多一次定向修复，禁止无上限的“直到模型满意”。阈值由小样本校准，不能随手设成某个概率后称为可靠。
- 传给修复模型的是具体失败维度及有关材料，避免整篇无目标重写。
- 修复之后重新检查受影响的剧情和画面描述；旧图不得配上新结局。
- 区分 `accepted`、`repaired`、`degraded`、`judge_unavailable` 等语义；具体字段可调整。失败或未评估绝不能记录成通过。
- JSON/schema 失败不能被模板转换后伪装成模型生成成功。
- 缺少凭证、超时、格式异常或低把握时保持原路径或明确兜底可用，记录原因。不要默认增加一整套新的 LLM 审核链，除非证据说明需要。
- `generateReplyForRecord` 与 HTTP 生成入口必须复用同一核心；测试也使用这套生产函数。
- 重复生成不能覆盖已公开故事、重置已解锁段落或导致重复图片调用。具体事务/锁设计按当前代码最小改造。

### 4.4 第一阶段交付

- 可开关的 JEV 接入与统一生成编排。
- 处境问题集、创作契约、验收问题集和确定性的决策规则。
- 结构校验、有限修复、失败降级和版本记录。
- 离线边界测试与真实调用验证入口。
- 一份有实际证据的对照报告，说明哪些改善、哪些失败、哪些未验证。

## 5. 第二阶段：生物事件与一句话留言实验版

仅在第一阶段工程闭环稳定后推进。第一阶段的真实 JEV 调用若暂时被凭证等阻塞，可继续独立完成事件引擎，但必须保留模型效果未验证的标记，不将实验开关默认开启。

### 5.1 最小范围

先做一只锦鲤、一种水域、三个事件节点、一轮可选留言和一封最终回信。先贯通现有 H5 入口，保持小程序旧路径兼容；小程序新玩法暂不属于默认完成条件。

不要先做复杂开放世界、实时地图运动、多角色社会、长期记忆系统和每日强制运营。

建议演示场景：

> 用户：“谁找我帮忙我都答应，最后只有我的事情没做完。”
>
> 事件：螃蟹请代班 → 水草请搬家 → 湖长请组织联欢会。
>
> 合法动作：答应、拒绝、协商、求助、离开。
>
> 用户可选留言：“这次你可以拒绝。”

首次拒绝可以导向另一段荒诞经历，例如被聘为海底劳动仲裁员。这里只是示例，不要求每次生成这个结局。

### 5.2 状态与分工

至少维护旅程 ID、记录 ID、状态版本、事件位置、行为倾向、资源/关系中实际需要的字段、已发生事件、留言、随机种子、终结状态和公开状态。

- 程序先筛选当前合法动作，JEV 只在合法集合里判断角色此刻的行为。
- 代码负责动作后果和状态迁移，LLM 不得直接自由修改权威状态。
- JEV 的模型置信度不能直接解释成角色性格或游戏行动概率；若要做随机选择，明确另设游戏策略、范围和种子。
- 只在事件节点调用模型，不按渲染帧调用。
- 事件顺序与状态更新可恢复、可去重；保存实际动作结果，重放时不重新询问模型。
- 留言先判断意图，程序只改变允许的行为倾向或下一节点条件。任意用户文本不能成为直接执行的系统指令。
- 留言与事件推进并发时，用状态版本或事务明确它影响哪个未来事件；过期留言不得修改已经发生的事实。
- 大模型根据已发生事件写回信，不得为了精彩补造与事件账本冲突的关键行为。

### 5.3 时间与体验

- 等待回信期间可以发生事件，用户不在线时旅程也能继续。
- 不回来、不留言不受惩罚；不要出现“你不照顾它所以它受苦”的强迫机制。
- 用户可以看到少量已发生的旅途片段，但不必反复打开页面才能推进。
- 延迟预生成与旅程推进要协调：最终回信只能根据已完成/已冻结的本轮事件生成，不能提前生成结局后再假装实时改变。
- 已展示事件和结局不可改写；回信后的留言归入下一轮或明确提示本轮已结束，不能默默重算。
- 支持测试用可控时钟或事件推进方式，复用生产调度逻辑；不要要求验收人员真的等 24 小时，也不要把测试入口无保护地暴露为线上任意推进 API。

### 5.4 第二阶段交付

- 默认关闭的实验开关、事件引擎、持久化和恢复机制。
- H5 中一条可操作流程：放生 → 查看进展 → 可选留言 → 查看最终回信。
- 从输入到事件、动作、后果和回信的完整追踪材料。
- 至少展示有留言与无留言两条路径；不以“随机种子不同”冒充留言产生影响。
- 旧功能在开关关闭时保持可用；实验不写坏历史记录。

## 6. 后续路线图：记录方案，本次不自动全部实现

| 方向 | 玩法与 JEV 机会 | 前提/边界 |
| --- | --- | --- |
| 故事机制去重 | 比较近期候选，识别“换了道具的同一故事”；优先看同一用户最近看过的内容 | 先检索有限候选，再做语义比较，不全库逐条比较 |
| 幽默偏好 | 用户明确选择“陪我骂两句 / 荒唐一点 / 今天轻一点”，检查表达是否越界 | 显式选择优先；不推断永久人格；基础验收中的贬低检查已属第一阶段 |
| 生物相遇 | 互补/冲突的行为倾向产生共同事件 | 先有稳定事件账本；公共参与需明确选择，不自动公开原始烦恼 |
| 群体世界事件 | 多个虚构角色的倾向影响水域故事，例如不断变形的办公楼 | 聚合、权限和可追溯性先于规模；不宣称当前已经匿名 |
| 故事档案 | 总结“这句话造成了什么后果”，连接真实放生记录与事件 | 只描述有证据的变化，不推断心理改善 |
| 分享卡 | 原话（用户可选）+ 生物经历 + 因果片段 | 用户主动分享，默认不外发 |

## 7. 验证设计：不能只看通过率

### 7.1 建立可复现基线

执行前保存当前代码版本/工作区差异摘要、实际模型配置中的非敏感字段、随机种子、问题集版本和测试条件。不要打印密钥、认证头或整个环境文件。

先整理约 24 条中文样本，覆盖常见处境、同情绪不同原因、反话、否定、混合情绪、积极情绪、极短输入、信息不足及边界表达。合成样本与既有记录明确区分；使用历史记录时只取必要内容，不扩散私人文本。

将问题开发/阈值校准用例与最终评估用例分开，报告具体样本数。不要看完测试结果再改标签或门槛后继续称为未见评估。

### 7.2 三层证据

| 层级 | 必须验证什么 | 能说明什么 |
| --- | --- | --- |
| 确定性/离线 | schema、标签组合、契约编译、降级、版本冻结、幂等、迁移、合法动作与留言竞争 | 工程行为满足条件；不能证明模型懂中文 |
| 真实生产路径 | 实际 JEV + 实际文本模型，经真实服务编排，持久化判断与结果；至少一条经真实配图路径 | 模型和系统实际连通；不能自动证明用户效果 |
| 内容效果 | 对照旧生成与新增判断，匿名打乱输出，由独立评估比较输入针对性、因果自然度、冒犯、重复、继续阅读意愿 | 小样本质量证据；不能当作留存、疗愈或商业结果 |

测试可以替换外部网络边界、使用独立测试数据库和临时输出目录，但必须复用生产决策、编排和状态迁移函数，不写一套仅用于测试的替代实现。

### 7.3 对照与成本

- 比较旧路径与“处境判断 + 因果验收”路径；控制文本模型、输入、随机条件和生成预算，披露不能控制的差异。
- 如果新增重写明显增加生成预算，增加一个相同生成预算的对照或明确说明无法区分收益来源。
- 同时查看误放行和误拦截。挑出模型高置信但错误、合理荒诞被误判和中文反讽失败的案例。
- 记录判断耗时、总生成耗时、调用数、修复率、降级率、可获得的 token/费用信息。拿不到实际计价时标记估算，不编成本。
- 在线 JEV 不能做唯一终审。若只有另一模型评审，标为“模型代理评估”；人工尚未评审就留下盲评材料和待评状态，不代写人工结论。
- 事件实验用相同初始状态和可控条件验证留言确实影响允许的后续行为；工程作用与用户吸引力分开报告。

首次真实调用只做少量连通性验证，例如最多三条故事、一张图片；这属于建议调用上限，不是用户已批准的费用额度。接收方按实际执行授权使用现有配置，不购买配额或擅自开启批量长跑。确认环境和预算条件后再运行完整对照。

## 8. 运行、降级与范围控制

- 尽量沿用现有 Node/Express/SQLite 结构，新增模块是为了共用核心逻辑，不为了展示框架复杂度。
- 功能开关至少能分别控制语义判断与事件实验；默认值与回退行为写入运行说明。
- 使用独立的测试数据库，或增加可配置数据库路径；不要把回归数据混入现有用户记录。
- 在实际启动前核对端口、运行中的服务和现有数据位置，避免误停其他进程。
- 没有 JEV 凭证时完成适配器、测试、降级和独立任务，并明确留下真实接入待验证项；不要伪造成功响应。
- 真实 JEV 中文效果差时，先缩小问题、调整准则或保留实验开关关闭。必要时比较传统代码/现有模型方案，不为了使用 JEV 强行上线。
- 本任务不包含重做全部 UI、替换数据库、引入多 Agent 系统、上线部署、真实广告接入或公共社交运营。
- 与目标直接相关的生成/幂等/冻结问题可以修复；其他发现记录在交付报告，避免把项目变成无限重构。

## 10. 完成条件与最终汇报

工程完成检查：

- [ ] 接收时的工作区基线已检查，既有改动已保护。
- [ ] 真实生成入口复用统一核心，不存在调度已改但手动入口绕过验收的问题。
- [ ] 四集结构、契约编译、语义判断、有限修复和降级已接通。
- [ ] 回信、画面描述和故事使用同一已接受版本。
- [ ] 开关关闭、模型不可用、低把握、超时和解析失败的路径有证据。
- [ ] 事件实验有合法动作、确定性状态迁移、持久化恢复、幂等和结局冻结。
- [ ] 留言有真实可追溯的后续影响，不能改写历史。
- [ ] H5 能走完实验流程；小程序旧行为兼容，新玩法支持边界说明清楚。
- [ ] 有复现命令、评估数据、关键失败案例和未验证项。

验证完成检查：

- [ ] 已运行适当的工程测试，明确测试覆盖与限制。
- [ ] 若具备真实调用条件，完成真实 JEV/文本/图片路径验证并记录实际版本。
- [ ] 内容效果通过独立对照检查；若只有模型代理评估，明确标记。
- [ ] 没有把合成结果说成真实用户数据，没有把接通说成质量提升。

目标结束时区分三种状态：

1. **实现与约定验证完成**：交付代码、证据、复现方式和仍属产品假设的部分。目标可以完成，但不得宣称未做的用户研究已完成。
2. **工程完成，外部验证待完成**：例如缺少凭证或必要人工评审。明确列出欠缺项；如果它属于当前目标的必需条件，不把目标假标为 complete。按宿主工具规则处理等待/阻塞，继续所有不依赖它的工作。
3. **JEV 不适合当前中文任务**：如有真实对照证据，保留可运行旧路径、关闭实验默认开关，提交失败分析和推荐替代。验证得到否定结论也是交付，但未完成的实现不能隐去。

最终汇报先讲用户能看到什么变化，再列测试证据、实际成本/时延、关键限制、开关和启动命令。不要仅以“所有测试通过”收尾；至少给出一组原始输入、故事变化及其判断依据。
