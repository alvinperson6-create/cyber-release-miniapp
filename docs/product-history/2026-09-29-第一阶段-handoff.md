## 1. 要达成的体验与已确认取舍

用户写下一件具体烦恼，选择一只生物和放生水域。生物带着自己的轻量目标进入一个不断展开的文字世界。LLM 提出遭遇和可行行动，JEV 根据该生物的持续动机及已经发生的事决定行动；行动带来后果，成为下一次遭遇的事实。生物可以在有意义的节点寄来可回应信号或阶段经历来信，而不是按预选日期寄唯一的终局回信。用户不必守着页面，旅程仍会继续；一程结束后可以跟随**同一只**生物再次出发。

用户已确认以下取舍，不要在实现时重新引入旧结构：

| 事项 | 本阶段决定 |
| --- | --- |
| 世界 | LLM 作为文字世界导演，按关键遭遇推进；不建设固定场所、预枚举事件库或完整物理／经济模拟。所选真实水域仍是叙事入口和氛围锚点。 |
| 生物 | JEV 是行动决策脑；具体烦恼形成持续动机档案，在每次有意义的行动决策中提供给 JEV。旧烦恼不被永久写成生物性格。 |
| 程序 | 掌握权威事实、合法性、调度、并发、预算和副作用。模型文字不能直接覆盖已提交事实。 |
| 对外内容 | 仅两类：**可回应信号**（未决选择前，可寄一句话）与**阶段经历来信**（可只讲本程某一阶段）。本程收束时的最后一封仍属于经历来信，以 `is_final` 等状态区分。 |
| 时机与寿命 | 不再提供 24h／3d／7d／自选终局回信时间。何时求助、何时来信和何时自然收束由生物在合法节点判断；程序只设最大静默、调用预算、安静时段等服务护栏。用户可主动结束本程，同一生物可再出发。 |
| 幽默 | 默认“荒诞但温和”；用户可以为本程选择“轻一点／更荒唐一点”，以后还能改，只影响未来遭遇的强度与表达，不改 JEV 行动或已经发生的事。笑点落在荒诞规则、处境与生物自身，不贬低用户。 |
| 旧产品 | 取消四集故事、结局先行、广告解锁和固定延时回信；旧数据**无需迁移或兼容**。旧模式只保留为产品演变资料。 |

本阶段**不做**“生物相遇＋共同世界”和用户可见的跨旅程“故事档案”（原方向第 4、5 项）；两者属于第二份 handoff。为运行旅程而持久化的内部经历账本、消息记录和生物身份，以及用户查看**本程**已收到信件的界面，不等同于第二阶段的故事档案。不要以第二阶段为由拖延第一阶段，也不要暗中做假相遇或公共分享。

## 3. 核心机制契约

### 3.1 持续动机与同一生物

用户提交放生后先保存输入并立即给回执，不让首个 JEV／LLM 调用阻塞可见成功状态；后台完成识别与首个遭遇前，界面如实显示“准备出发”。用原话及可追溯的证据句建立版本化的**本程动机档案**：具体压力、可能的行动倾向、证据和不确定性。没有足够证据时如实记为未识别／证据不足，不把抽象情绪硬判成稳定人格；识别不可用时保留待重试状态，不用伪造档案启动自主决策。每次 JEV 行动判断都必须收到这一档案、当前生物目标、已发生的相关事实、可选动作和在时限内收到的用户补给。用户留言是决策证据，不是覆盖动机的命令；不能把“你可以拒绝”程序化地强制映射成此后永远拒绝。

同一生物有稳定 `creature_id`；一次出发有独立 `journey_id`。新旅程可引用同一生物真实经历中必要的事实，使用新的用户原话建立新的本程动机版本，不把旧烦恼永久固化。界面要能明确选择“让这只生物再次出发”；同物种的新生物不自动等于同一个体。第一阶段可先保证同一受保护的浏览器身份下可找回，跨设备同步不作虚假承诺。

### 3.2 LLM 导演、JEV 决策、程序提交

开局由 LLM 给生物一个轻量自身目标和首个遭遇；无需为每只生物编一条宏大主线。此后在**关键选择节点**推进，不按动画帧或全天候流式调用模型。一次导演调用可结算上次已选行动的环境后果，并提出下一次具体遭遇，以降低模型调用数。放生水域可影响开场和氛围，但不要求所有事件被固定场景素材决定。

导演提案至少包含：当前处境、由既有事实引出的约束、2–4 个含真实代价且当下可行的行动候选、压力／两难／可能代价的**候选机制摘要**、预期可能改变的事实类型。行动后才能确定真正后果，并补成完整机制卡。候选行动是动态生成的，不是旧的全局固定五动作；给 JEV 留“这些都不合适”的出口，触发有限重提案。导演可读抽象处境契约、目标与已提交的世界事实，不必反复拿用户原话把每个怪事写成烦恼隐喻。JEV 读自己的完整本程动机证据，从合法候选中选择；导演不能代替它选行动，也不能在后果里写成它做了别的事。

程序先验证并冻结一份待决遭遇提案（含合法动作与状态版本），再由 JEV 选择行动或先寄信号；选定行动后由 LLM 结算环境后果与最小事实增量，程序校验并将行动、后果和状态变化原子落账。模型调用在事务外，已选择但尚未结算的行动有明确待完成状态，不能提前向用户宣称后果。一次导演调用可以顺带提出下一遭遇，但前一件的后果与后一件的提案须各自按版本提交，下一提案失败不能抹掉前一件。至少保留地点／去向、目标、承诺、重要资源与物件、关系、未了之事、已选行动、后果和下一次触发条件；只保存故事确实用到的事实，不扩建全量世界模型。每件已公开或已提交的事有稳定 ID 和版本，模型失败、重试和页面刷新都不能改写它。

### 3.3 两类联系、节奏和收束

在尚未做出关键行动时，JEV 可以选择“先寄可回应信号”。此时冻结具体的 `encounter_id`、候选动作、状态版本和补给截止时间，持久化一条 `pending_signal`；LLM 只根据这件未决处境写简短信号，清楚说明问题与可选的一句话补给，不剧透后果，也不以“你不回我它就受害”施压。用户不回复，到期任务也必须唤醒同一件遭遇，再由 JEV 在原合法候选中决策；同一遭遇不反复选择“再寄一次信号”，页面是否打开不影响推进。按时回复只进入这次**尚未提交**的 JEV 决策。回复与到期同时发生时，由服务端时间、状态版本和一次性提交确定胜者；迟到回复不得改写已发生的选择，可明确标为仅供本程之后的未决行动参考。本程已经结束则不悄悄带入下程。

经历发生后，JEV 在有意义的检查点决定继续、寄一封**阶段经历来信**，或自然收束并寄本程最后一封经历来信。阶段来信不必概括整段旅程，只能叙述已提交的事实及生物的视角；信中可以留悬念和未了之事。回信由 LLM 写，生物行动仍由 JEV 决定。程序负责安静时段、最小发送间隔、最大静默、任务预算和过期处理；服务性状态提示要与“生物主动寄信”区分。用户随时可结束本程，新事件立即停止排程；结束操作不等待模型写漂亮结尾才生效。预算／模型故障导致的暂停或中止要如实显示，不伪装成生物自主收束。

用户看到的是本程状态和**已寄出的**信号／经历来信，不能因为后台发生一件事就把所有隐藏遭遇即时公开，从而取消生物自己选择来信时机的意义。关闭回执后仍能回到本程信箱；打开页面只读取状态，不应成为旅程推进的必要条件。

### 3.4 故事机制去重与幽默边界

去重对象是因果机制，不是道具、地点或行动标签。每个已结算遭遇留一张短机制卡：**压力来源—真正的两难—实际选择代价—持久后果**。新提案参考最近几张完整卡及当前未了之事，用候选摘要预防明显换皮；提案时尚未发生的后果不能伪装成事实。生物反复答应可能恰好是持续动机的真实表现；如果旧选择导致新的约束、代价或结果，允许有目的的回环，不为追求新奇强迫 JEV 改变性格。保留少量跨本生物前次旅程的机制摘要即可，不建设用户可见的故事档案或全局相似度库。

仅在**未公开、未提交**且明显连续重播时允许最多一次定向重提案；可疑但不确定的相似性记日志并进入抽样评审，不做每轮全库 JEV 终审，也不因审美分数自动重写已发生故事。JEV 可用于有限候选间的窄语义比较，不能充当“好不好笑”的唯一裁判。

幽默来自荒诞规则、错误激励、意外代价和生物认真面对离谱局面；不把用户的痛苦、能力、人格或用户未提供的个人事实当包袱。停止旧提示词“每封都要很惨又很好笑／炸裂反转”的要求，允许平静、意外、尴尬或偶尔不抖包袱的段落。可回应信号只用轻微荒诞，阶段来信可更放开。语气偏好调整**未来**导演提案的荒诞程度与 LLM 文风，不能理解为加重用户的痛苦；它不直接覆盖 JEV 的决策或改写已承诺的事实与过去来信。未来遭遇改变后，JEV 的后续选择可以自然不同。用户自嘲也不能被放大成人身评价。程序和窄语义检查优先拦明显贬低、编造用户事实、以回复施压、行动／后果矛盾，仍须用人工阅读判断有趣与被尊重感。

### 3.5 配图与成本

以文字体验先成立为前提。信号和每个遭遇不必配图；实施默认是单程最多为一封重要经历来信或收束信尝试配图，额度做成可配置项并记录实际用量。图片只从已确认的来信及画面事实生成，不能阻塞文字送达；生成失败仍可正常读信。当前只能核对画面提示与文本约定、图片是否落盘，最终图片质量另需人工查看。事件数、最大静默、总调用数与 token／图片预算由执行 Agent 给出保守可调默认、实测并写进运行手册；它们不是用户已拍板的固定剧情长度或发送日期。

## 4. 实施顺序与必须处理的旧入口

1. **基线与数据边界**：记录当前工作区差异、旧测试状态和模型配置中的非敏感字段。新 schema 可从空库开始，旧数据无需迁移；测试使用独立 `DB_PATH`，不把个人原话或密钥写进仓库。调整服务端 `seedDemoData()` 和 H5 的本地演示记录初始化，不能在新空库或首访时自动灌旧四集示例。保留上一轮文档和原始证据作为历史，不改写为新版结果。
2. **权威旅程内核**：建持久生物、旅程、事件、决策、事实、消息／回执和模型调用记录；必要字段含所有者、状态版本、`next_due_at`、任务 lease／重试键、决定来源及动机版本。模型调用在数据库事务外，提交使用版本条件与短事务；重复调度、进程重启或并发留言不得产生双事件、双信或把旧快照覆盖新事实。读取 API 不触发模型生成。任务按到期时间公平取用，不能让早期常驻旅程饿死后续旅程。
3. **共享编排核心**：复用可用的 JEV 适配、处境识别和模型调用边界；替换固定事件／固定后果、四集提示词、四集验收、单回信预生成与倒计时。`POST /api/release` 先持久化并迅速返回 `preparing` 回执，开局由后台持久任务完成。停挂或移除旧 `/api/destiny`、`POST /api/reply/generate`、旧 `JOURNEY_ENABLED` 分支和按 `reply_at` 预生成的调度路径，不能让旧入口继续生成四集或冻结新旅程。后台调度、必要的 HTTP 操作与测试都调用同一生产编排函数。JEV／LLM 超时先重试或暂停，不让 LLM 偷代 JEV 决策，也不把模板动作标成真实自主行动。每次降级有可追踪状态。
4. **H5 可用流程**：放生可选新生物或同一生物再出发；显示当前旅程与已寄出的信、待回应信号、语气偏好和结束操作。移除固定回信时间、四集弹窗、模拟广告解锁与误导性倒计时。关闭放生回执后能回来读本程信件；不在线仍会推进。由服务端签发不可猜的匿名会话凭据（如 `HttpOnly`、`SameSite` cookie，或等效安全机制）绑定所有者，客户端自报的 `openid` 与可猜记录 ID 均不能单独作为授权。所有读取原话、信件和写入补给／结束操作的入口都校验归属；会话凭据不进日志。渲染模型和用户文本时做安全转义。
5. **其他入口处理**：真实小程序及 `cyber-release-miniapp.html` 若未同步重做，就作为历史原型停用／从新版导航移除，明确不属于本阶段已验证客户端，不让旧流程与新版 API 同时对用户宣称可用。作为隐私安全处理，关闭当前公共“世界脉搏”对他人原话片段的展示，或改用完全不取用户原话的环境文案；这不是用户要求新增公共玩法。
6. **机制多样性、幽默与配图**：接入机制卡、有限重提案、语气设置和新消息边界，最后接非阻塞的可预算配图。不要为了通过旧四集测试而保留已砍掉的产品行为。

## 5. 验证与交付证据

测试须复用生产编排和状态迁移，可替换模型网络边界、注入时钟并使用隔离数据库。旧 `node --test "tests/*.test.js"` 的 61 个用例证明旧机制回归，不能替代新旅程验收；按新接口改写相关用例。至少覆盖：

- **持续性**：同一具体处境在多个 JEV 行动请求中持续携带证据与最新档案；新旅程沿用 `creature_id` 但换 `journey_id` 和新动机版本。未识别处境和后来留言不被伪装成永久人格。
- **动作与事实**：LLM 提案含合法且有代价的不同动作；JEV 实际选择及来源落库；后果不得改变该动作，下一遭遇承接旧事实。无合适动作、导演矛盾、模型超时和重试均有确定行为。
- **联系与寿命**：同一测试旅程能先有可回应信号、再有非终局经历来信、继续行动、最后收束；不回复不阻塞，迟到回复只影响未来；用户结束后不再生成本程事件。用可控时钟证明无固定终局延迟、调度无需页面在线、静默／预算护栏有效。
- **去重与幽默**：“换道具但压力／两难／代价／后果相同”能被识别或避免；“生物行为相似但旧后果带来新取舍”不被误杀。记录是否重提案；明显贬低、虚构用户事实、信号施压、来信与账本冲突有拦截或如实降级。语气变更只影响未来，不能覆写旧事实。
- **并发与安全**：调度重入、重复 HTTP、回复与行动竞争、进程重启后恢复、状态版本冲突、越权读写、猜 ID、前端注入及图片失败都跑通。未实际调用 JEV 时不得将动作来源标成 JEV。

做一轮**真实生产路径**小规模验证：真实 HTTP＋现有文本模型＋真实 JEV＋真实 SQLite。至少一条旅程应串起信号 → 按时补给或超时无补给 → JEV 行动 → 非终局经历来信 → 继续行动 → 自然收束，并用同一 `creature_id` 再开一程；另用不同处境覆盖动机差异。用可控时钟加速生产调度，不写测试专用决策逻辑。手动结束和后台重启恢复也要通过真实服务路径验证；若预算或外部服务限制无法跑完，列明未验证环节，不勾对应完成项。如运行配图，先限一张。记录模型版本、提示词／契约版本、状态轨迹、token、时延、重试和降级；不可用时明确列为未验证，不造成功日志。内容效果另做同一处境多种遭遇的盲评材料，检查换皮、因果自然度、好笑程度、被尊重感和继续阅读意愿；若无人类评审，就只交材料并标“人工未评”，不能把另一模型的评分写成人工结论或留存改善。

交付时在 `docs/` 下提供新版设计、运行手册、验证报告与进度记录，写明真实完成项、失败案例、模型费用／用量及未验证项。旧 `docs/jev-*` 保留为前一轮证据。最终报告要能从一条用户输入追到动机档案、事件提案、JEV 实际动作、后果事实、信号／来信、结束状态，并说明第二阶段第 4、5 项未做。

## 6. 完成标准

- [ ] H5 与后端的真实主链已改成动态单生物旅程；没有可用的新入口仍要求选固定终局日期、预看四集或看广告解锁。
- [ ] 一只生物能在不同出发中保持身份；本程动机持续供 JEV 决策，新烦恼不会被旧档案吞掉。
- [ ] 事件由 LLM 临场提出，合法动作由 JEV 实际选择；程序记录并守住不可改写的因果事实。固定三节点／规则回退不能伪装成此成果。
- [ ] 两类联系、非终局来信、无响应继续、主动／用户结束及后台自主推进均能从真实 H5 流程操作和恢复。
- [ ] 机制去重与幽默边界在生成前发挥作用，有限检查不会默认反复重写公开内容；“轻一点／更荒唐一点”只对未来生效。
- [ ] 旧四集／广告／旧数据兼容负担从新版生产路径移除；未改造的客户端不会继续宣称旧路径是新版。
- [ ] 离线、真实模型连通与内容效果三层证据分开报告；人工未评、图片未评、预算与故障边界都如实说明。
- [ ] 生物相遇／共同世界与用户可见的跨旅程故事档案没有混入本阶段，留待第二份 handoff。
