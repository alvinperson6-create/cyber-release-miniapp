## 3. 目标结构与允许的实施选择

以下是候选目标，表达必须建立的边界。执行者可调整目录名与拆分粒度，但需在设计报告中给出最终路径与等价检查规则；不能只留文档约定。

```text
shared/
  contracts/                 # 浏览器与服务共用的公开契约、纯校验
renderer/
  entrypoint
  edge/journey-api           # 业务 HTTP 通信入口
  features/
    release/
    mailbox/                 # Client、副本、草稿、消息卡片
    timeline/
serving/
  entrypoints/               # 无副作用 createApp、生产装配和启动
  features/journey/
    commands/
    queries/
    workflows/
    context/
    policies/
    commits/
  adapters/                  # SQLite、文本模型、JEV、图片与调用记录
tests/
  scenarios/
  integration/
  browser/
tooling/
docs/
legacy/
```

Feature 是业务能力；Entrypoint 是装配／启动入口；Client 持有后端副本并提交命令；Host 掌握业务权威；Transcript card 对应信号、经历来信、系统提示及回顾节点。五类是职责词汇，不要求每个短函数都生成五套文件。

保留单 Node 服务与 SQLite；HTTP 继续承担跨边界通信。HTTP 与 worker 可有独立装配模块，但默认可仍在同一进程启动，避免意外启动两个 scheduler。不引入微服务、通用事件总线或大型自研框架。TypeScript 可从公开契约和关键边界渐进迁移；最终必须有有效的类型／契约检查，不要求第一步全量重写 JavaScript。

### 3.1 必须由工具检查的依赖规则

- renderer 仅通过 edge 调用业务 API，不能导入 serving、数据库、模型凭据或 Node 专属业务实现。
- shared 仅含公开类型、枚举、纯 schema／校验及适合共享的纯数据；不能导入 renderer／serving 或含 IO、环境变量读取、密钥与初始化副作用。内部数据库行、ownerKey、提示词和模型响应不成为公开 DTO。
- queries 只获得读取能力，不能调用模型或写入业务状态。对只读 adapter 的依赖允许，但不能取得原始数据库写接口。
- 模型 adapter 返回模型结果，不拥有故事事实提交权。提示词构造和 schema 校验是纯模块，不访问数据库或网络。
- workflow 编排读取、外部调用、校验与提交；不得绕过明确的 commit／command 接口直接写表。原始 SQL 及事务实现集中到存储适配层。
- commit 协调业务条件与短事务，通过存储适配器执行原子写入；commit 事务内不能调用模型。
- 生产路径不能依赖 legacy 或测试场景。测试可调用生产模块并替换允许的依赖。

边界检查同时覆盖迁移期间仍存在的 JS、CommonJS、相对路径和公开包入口。CI 必须包含代表性的违规样例或检查器自测，证明规则确实会失败；不能凭一个绿色空配置宣称已强制边界。

## 4. 实施顺序与各阶段出口

### 阶段 A：基线、发布资源与生产共用装配

1. 保存基线，运行现有离线套件并记录实际结果。历史 39／43 等数字是旧记录，本轮执行结果单独记录；先区分已有失败与新增失败。
2. 静态服务仅公开明确的 H5 文件／构建目录和必要公共资源。不能公开仓库、serving、legacy、运行数据库或测试产物。支持 SPA 时，私有路径不能被静态文件或错误 fallback 暴露。
3. 提取无启动副作用的 `createApp(runtime)` 与 runtime factory。导入模块不监听端口、不启动 timer、不连接生产库、不触发模型。
4. production、HTTP 测试和场景开发服务共用 createApp。启动入口负责实际配置、依赖装配、DB 初始化、调度和监听；runtime 可以 stop／close 并释放资源。
5. 保持生产启动可用，以及现行 v2 API、H5 和已有消息图片 URL 可达；退役的 destiny／records／四集原型不要求恢复或兼容。搬前端资源时同步修复地球、纹理、地图配置及图片路径。

出口：实际应用装配的 HTTP 检查通过；私有源码、模拟私有数据和 legacy 不属于公开产物；现有隔离库可以被新版读取。静态安全验证使用临时模拟文件或 HEAD，不抓取生产数据库内容。

### 阶段 B：最小可复现验证底座

复用现有 SQLite、生产编排、scheduler.tick 与可控时钟。建立实例级依赖注入：store、clock、配置、director／JEV adapter、图片 adapter、调用执行器／telemetry。两个 runtime 的库、时间与桩互不污染，不再依赖 require 顺序、全局模块导出替换或提示词关键字。

模型操作有显式名称，例如 opening、proposal、settlement、signal_write、letter_write、final_letter_write、situation_recognition、action_decision。确切命名可调整，未知操作在 fixture 中明确失败，禁止回退真实网络。

每个主场景通过“实际命令 → 生产任务 → 固定 adapter 响应 → 生产校验／提交 → HTTP 读取”建立。允许另设快速 UI seed，但必须标注 `seeded-view`，不能用其替代主链验收。fixture 不需要生产密钥，默认断言零外部调用。

实现一个场景启动／重置／步进入口，输出地址、场景、运行模式与产物路径。fixture 控制只存在于本地测试／开发装配，不挂到生产 API；所有 reset 只作用于该次隔离数据。

出口：执行者及后续 Agent 可用文档中的一条实际命令进入 preparing、待回应信号、来信与已结束等场景，自己复现并观察，不需要用户手动制造条件。

### 阶段 C：共享通信契约与命令幂等

1. 共享 Release、ReplyToSignal、SetTone、EndJourney 命令及结果、JourneyView、列表、Timeline、消息 kind 和错误码。输入、外部响应及持久任务 payload 在相应边界运行时校验；HTTP 序列化只输出明确 DTO。
2. 保持当前 v2 API 路径与会话规则。ownerKey 从服务端会话获得，不接受客户端自报所有权。
3. 回复明确传 signalMessageId／encounterId；Host 核对目标、归属、当前状态和截止时间。截止已过或该目标已决，但目标可追溯且本程仍允许留言时，明确记录 ontime=false／late，只作本程后续未决参考，不占新信号补给位、不改原决定。目标不存在／越权或本程已结束时按契约拒绝；其他冲突给明确结果，不能自动绑定最新信号。
4. 命令有 requestId／等价幂等键，按 owner 与操作分域；同键同 payload 返回稳定结果，同键不同 payload 返回冲突。建程、回复、结束的去重结果与业务变化在同一原子边界持久化，重启后仍有效。
5. 截止等号语义、版本要求与错误状态码在契约中固定，并与 UI 一致。版本锁按命令需要设计，不给所有请求机械套同一 expectedVersion。
6. 同步更新 H5、验证脚本和调用方。必要旧字段兼容应显式、有限且记录；缺少回复目标不得以静默推断最新信号作为兼容方案。

出口：并发／回包丢失后重试只创建一程、一条有效回复及一次结束提示；不同 owner 的幂等键互不串用；旧信号请求不会影响新信号。

### 阶段 D：Host 提交、调度与模型调用边界

把用户命令、公开查询、各 workflow、context、策略与 commit 分离。优先封住状态提交权，再迁移具体 handler。小型业务专用接口即可，不构建允许任意 patch 的通用提交平台。

**每项有副作用的操作在模型 await 后、提交时复核：**

- 当前旅程是否允许该变化，状态／相关版本是否仍匹配。
- 遭遇、已选动作、信号及补给等决策输入是否仍对应生成时的有效快照。新增按时补给不能被旧的无补给决策悄悄吞掉。
- 当前 task 是否由本 worker 的有效 lease 持有；旧租约结果不可写入。任务完成／重试／失败本身也必须条件更新，不能覆盖新租约或 cancelled 状态。
- 操作是否已提交；使用稳定 operation ID 或等价唯一约束，不用“检查后再插入”的非原子去重。

提交结果区分 applied、already_applied、stale、cancelled 等实际含义，trace 不把所有结果笼统记成“完成”。operation ID 绑定具体逻辑任务／联系检查点，不能简单以 journey ID＋letter 去重，否则会拦住合法的多封阶段信。

事实、机制卡、消息、旅程状态／版本及必要后续任务或排程意图在相应短事务内一起提交；不能出现落账成功但永久丢下一步、重复寄信或终态复活。重启后恢复已接受的后续决定，不重新询问模型改变它。reconcile 保留可恢复能力，补任务需按有效业务目标去重；历史记录缺少排程意图时采用明确标注的兼容恢复策略，不伪造原决定。

用户结束立即生效。无法取消的在途网络请求返回后必须丢弃业务提交，不能把 ended_user 改成 ended_natural、追加剧情或重新排任务；其真实调用用量仍记账。例外仅是给已存在信件补图，须验证消息归属和原操作，不创建新信或推进剧情。

调度结果明确区分完成、正常 defer／等待、错误 retry 和永久失败；正常等待按明确 dueAt 排程，不耗错误重试次数。错误采用受限退避；重复 tick／重入及崩溃后的旧 worker 均受租约与提交约束。

统一模型执行入口覆盖处境识别、JEV 决策／检查、LLM 生成／修复与图片的相应预算。区分逻辑 operation 与 transport attempt，覆盖适配器内部重试。每次真正的网络尝试，包括失败和修复，均按规则记账；无网络调用的预算拒绝与实际调用分开记录。若存在并发调用，预算检查与占用需原子化，不能各自看到余额后超额。不给每个 handler 留一套可绕开的裸模型入口。JEV 行动判断不可用时继续重试／暂停，不以规则动作冒充 JEV 决策。

统一 context builder 明确原话、可用证据、既有事实、当前按时补给、迟到参考的范围。本程有效的迟到回复在后续未决选择中可追溯使用，不影响已提交动作，不跨程。此项修复原有承诺，不新增用户指挥生物的能力。

telemetry 至少关联 request／journey／encounter／task／operation／model call，记录耗时、结果、重试、提交拒绝和预算来源。凭据不进日志；默认诊断产物使用合成输入，避免复制实际用户原话。成本未知时记未知，不伪造费用。

出口：结束／补给／租约／预算竞态有确定结果；所有新增故事事实都经过受控提交；纯 query 与提示词模块不能越权。

### 阶段 E：Client 与消息卡片

服务端视图按 journey ID 存放；草稿按 signal ID 存放。选中旅程、请求状态、输入、展开状态与服务端快照分开；命令完成后以 Host 返回／重新读取的结果确认状态。

切换旅程取消旧请求，并在应用响应时检查 journey ID 与请求序号／请求代次；AbortController 本身不能替代晚回检查。同一旅程乱序响应和命令完成前发出的旧轮询，也不能覆盖已确认的新视图。非法响应如实报错，不写入缓存。

**不要直接将现有 state_version 当作完整前端 snapshotVersion。** 现行版本主要服务事实／决策并发，未覆盖每次消息、语气或图片变化。可先采用请求序号与命令后的失效机制；若增加公开 snapshotVersion，先定义全部可见变化如何推进，再验证。

消息按稳定 ID 更新；轮询不丢回复草稿、焦点及用户选择的展开状态。保留文本转义及模型文本安全渲染。信号目标改变后不能悄悄将旧草稿作为新信号回复；过期、提交中和失败状态清楚可见。

出口：真实浏览器覆盖错旅程晚回、同程乱序、命令与旧轮询竞争、草稿保存和回顾展开；验收正常地图／地球、配图与再次出发路径。

### 阶段 F：自动检查、知识入口与归档

1. 根目录提供统一 check，包含依赖边界、类型／schema、离线业务、生产装配 HTTP、关键浏览器回归及构建。可另提供快检查，但最终 check 不得静默跳过必要项；失败返回非零并指出检查、场景和产物位置。
2. 默认 check 不需要真实模型、生产数据或付费服务。真实模型连通／回放单独命令，明确使用隔离数据及实际费用／用量。
3. CI 运行同一入口并阻止失败变更合入；若远端 branch protection 无法配置，记录本地与 workflow 已完成、远端强制状态未验证，不能声称远端已经拦截。
4. 仓库 README 和 AGENTS.md 指向唯一现行入口、模块边界、运行／验证命令、数据位置与 feature map。遵守既有用户提供规则：公众号优先 opencli weixin download；存想法使用 thought-vault，不将本轮工程规则覆盖这些要求。
5. 一份项目验证 Skill 说明场景选择、操作、证据收集、失败处理与判断边界，并调用实际工具；不要仅写“请自行验证”。先采用仓库内可发现文档，不改用户全局 skills 配置。
6. 功能地图记录如何到达、场景前提、稳定 locator、对应命令、Host／UI 预期变化及验证位置。优先可访问名称；动态卡片用稳定业务 ID。迁移旧 ID 时同步更新检查，不能保留过期导航文档。
7. 功能模板只生成有意义的契约、Client／Host 入口、边界和必要检查；附一个已完成的最小示例。用已有功能验证模板，不为测试模板增加新产品功能。
8. 旧客户端和静态原型移入明确 legacy 范围，抽出仍使用的共享资源，并更新引用／脚本。历史验证、设计和产品演变材料保留；停止把旧例子当成现行 API 说明。

出口：后续 Agent 可以从 README 找到改哪里、怎么跑、怎么验证；违规实现自动失败，历史路径不混入生产产物。

## 5. 必须验收的场景与后果

以下是最小集合，可合并用例，避免测试仅复述实现。

| 场景 | 必须观察到的后果 |
| --- | --- |
| preparing → 开局 | 命令先给回执，后台生产编排后才有目标；重复 GET 不改变事实、任务和模型调用数。 |
| 待回应信号 | 实际编排产生信号；控制时钟验证截止前、等号和截止后；未到 sentAt 的内容不可见。 |
| 并发建程／回复／结束 | 同 owner 同幂等键同输入只落一次业务结果；同键异输入冲突；重启后结果稳定。 |
| 旧信号、过期与补给竞争 | 旧信号不能绑定新信号；按时补给进入对应有效选择；晚到参考只进入后续未决上下文，不改过去。 |
| 模型调用期间用户结束 | 用可暂停 adapter：调用开始 → end → 释放响应；无新剧情／事实／来信提交，终态不复活；已有信件补图独立验收。 |
| 旧 worker 与新租约 | 释放旧调用时无法提交或改变新 worker 的任务结果；一个业务 operation 至多落一次账。 |
| defer 与故障 retry | 多次正常等待不触发重试耗尽暂停，到期按原遭遇继续；真实错误按策略退避并如实暂停。 |
| 预算与调用台账 | 识别也记录；修复与失败真实尝试记录；无余额不开新请求；并发不超预算；取消后已发生调用仍有记录。 |
| 阶段信／收束与重启 | 阶段信后继续；自然收束后终态稳定；提交与后续任务不双写／丢失；配图失败不阻塞文字。 |
| Client 浏览器回归 | A→B 后 A 晚回、同程响应乱序、命令与轮询竞争都不回退；轮询保留草稿／展开状态。 |
| 所有权与公开资源 | 跨 owner 读写拒绝；公共脉搏无原话；源码、数据库、legacy、fixture 控制面不能被生产静态服务公开。 |
| 迁移后的既有库 | 原 creature／journey／message／fact ID 和内容不变；pending task 升级后能继续；重复迁移无重复字段／任务。 |
| 检查器与装配隔离 | 非法 import、query 写入、adapter 绕过调用预算会被相应检查拦住；两个 runtime 不串库、不串时间／桩；关闭后无遗留端口／timer。 |

种子展示、受控 fixture、真实外部服务、人工内容评价四种证据分别标注。fixture 证明受控输入下的装配、状态和 UI；不能证明真实 JEV 会选择该分支。真实模型没有走到阶段信等分支时如实标未覆盖，不用强制桩伪装实证。

重构完后做小规模真实生产路径冒烟，使用隔离数据库：至少验证真实开局／决策／结算／读取及一条结束或收束路径。固定场景仍是竞态与稀有分支的主要回归手段。外部凭据／服务不可用时保留源码和离线证据，标明真实连通未验证；不能编造成功或无限等待随机分支。叙事好笑程度、被尊重感、情绪价值和留存不属于本轮已证明结论。

## 6. 效率收益怎样记录

本轮目标是开发交付效率和可靠性，不能直接承诺旅程运行更快或 token 更少。新增校验与记录也有运行开销，应实测。

选取代表性维护任务，如调整来信表达、修复轮询草稿、定位结束后的旧提交。记录定位／实现／验证／返工耗时、人工补充或搬运次数、重复失败类型、验收后重新打开次数。对照需注明任务、模型、环境、验收条件和是否存在熟悉度差异；不能用测试通过数或 PR 数替代效率。

若有可靠前后对照，报告实测结果与限制；若没有，交付测量入口及记录模板，写“效率效果待实测”。不为了填数字重复无意义任务，不声称已经获得百分比提升。

每个本轮失败按性质处理：修复当前实例；再判断是否可复现、是否值得泛化。知识遗漏进 Skill／feature map；机械操作进脚本；可静态识别的违规进检查器；不合法输入进契约；重复越权写入收紧能力与提交入口。至少记录本轮实际发生的案例及其新增约束，不凑五类数量。

## 8. 给执行 Agent 的起始指令

读取本交接，先复核当前 HEAD、工作区、真实入口与旧验证记录。保留既有改动及 journey-v2 数据，完成阶段 A／B 的最小验证底座，再按 C–F 渐进重构；每个阶段保持可启动并跑相关检查。

目录树是候选结构，职责、通信、提交和自动检查要求是验收约束。可以调整实现细节，不以全面重写、微服务或新产品功能扩大范围。必要时先固定共享契约，再并行前端、Host 与验证工作，避免多人同时修改同一核心文件。

持续更新进度和证据。发生失败时先复现／定位并修复，再选择合适的环境约束；不要只增加提示词要求。最终给出实际变化、验证结果、数据迁移结果、效率记录和未验证项。任何运行限制都不能被改写成成功证据。
